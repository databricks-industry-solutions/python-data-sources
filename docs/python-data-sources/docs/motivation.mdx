# Motivation

Apache Spark ships native readers for the formats most analytics workloads encounter — Parquet, JSON, CSV, Avro, Delta, JDBC, Kafka. Outside of that mainstream, the long tail of file formats and streaming protocols is mostly served by a patchwork of one-off scripts, JVM connectors that are hard to install, or bespoke ingest jobs that re-parse data byte by byte.

The [PySpark DataSource API](https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/datasource.html) introduced in Spark 4.0 changes that: any Python class can implement `DataSourceReader` / `DataSourceWriter` and be addressed by `spark.read.format(...)`. **`python-data-sources` is a collection of those Python-native connectors** for formats and protocols that don't have a built-in Spark reader.

## What it covers today

| Connector | Read | Stream | Notes |
| --- | :-: | :-: | --- |
| `mcap` | ✓ | — | MCAP container format used for robotics, AV, and ROS bag logs. |
| `mqtt` | — | ✓ | MQTT broker as a Structured Streaming source. |
| `zipdcm` | ✓ | — | DICOM medical images packaged inside ZIP archives. |

## Why a single repo

- **One Python wheel** with optional extras (`[mcap]`, `[mqtt]`, `[zipdcm]`) so downstream projects pull in exactly the dependencies they need.
- **Shared utilities** — schema inference helpers, partition planning, and test fixtures live in a `common` module that every connector reuses.
- **Single test suite** running on every Databricks Runtime Spark version, so a connector that says it works on a given runtime really does.

## Where it fits

If you're prototyping a new pipeline on Databricks or open-source Spark and need to land MCAP / MQTT / DICOM data into Delta without writing a parser yourself, register the connector and call `spark.read.format("…")`. The output is a normal DataFrame and behaves like any other source — partitioning, schema evolution, and streaming semantics all work the same way.

If you need a connector that isn't here yet, [open an issue](https://github.com/databricks-industry-solutions/python-data-sources/issues) — the contribution process is in the repo's `CONTRIBUTING.md`.
